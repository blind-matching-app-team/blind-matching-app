# S9 매칭 대기 (BMA-65)

사양서 v1.5의 S9-01~09를 `/matching/waiting`에 구현한다. S4 저장 후 본인인증이
완료된 경우 바로 S9, 미완료인 경우 S15의 목 인증 완료 후 S9로 이동한다.
S5의 매칭 시작도 같은 경로를 사용한다. 사이드바 없는 독립 화면이다.

대기 시간은 큐 등록 시각으로 계산하며 1초마다 갱신한다. MSW는 5분 경과 시
`empty`를 반환한다. 새로고침은 기존 큐와 시작 시각을 유지한다. 다시 시도는
만료된 큐를 새 큐로 교체한다. 취소 및 뒤로가기 버튼은 확인 모달을 거치며,
삭제 성공 후 S5로 이동한다. 취소와 매칭 성공이 겹치면 완료된 매칭을 우선한다.
통신 오류에는 재시도와 취소를 제공하며 정상적인 매칭 없음과 구분한다.

## MSW 시나리오

개발 서버에서 브라우저 콘솔로 아래 값을 설정한 뒤 S9에 진입한다.
기존 큐가 있으면 먼저 대기 취소한다. 목 데이터는 사용자별 sessionStorage에 보관한다.

```js
sessionStorage.setItem('bma-matching-scenario', 'waiting');
```

| 값                 | 동작                                     |
| ------------------ | ---------------------------------------- |
| `waiting` (기본값) | 5분 대기 후 매칭 없음                    |
| `empty`            | 3초 후 매칭 없음, 빠른 UI 확인용         |
| `matched`          | 3초 후 기존 열린 목 채팅방(S10)으로 이동 |
| `exhausted`        | 큐 생성 없이 CM-13 소모형 모달 표시      |

`/api/mock/matching/queue`의 POST(등록/재접속), GET(상태), DELETE(취소)를 사용한다.
실제 API 연동과 결제는 별도 작업이다. 기존 CM-13 구현이 없어 공통 Modal 기반
소모형 진입 화면과 준비 중 안내를 제공한다. 상품·가격·결제 성공을 가정하지 않는다.
PDF 원본 미제공으로 카드 여백 등은 기존 UI 톤에 맞춘 값이며 원본 대조가 필요하다.

검증: frontend에서 `npm run build`, `npm run lint`.
개발 서버를 3000번 포트에서 실행 후 qa에서
`npx playwright test --project=e2e matching-waiting.spec.ts`.
설치된 Chrome 사용 시 `PLAYWRIGHT_CHANNEL=chrome` 환경변수를 설정한다.
