# S11 Phase 2 채팅

개발 서버에서 `/`의 **대화 시작하기** 또는 `/chat`의 방을 선택하면 `/chat/:id`로 진입합니다.

- 메시지는 MSW `POST /api/mock/chat/:id/messages`로 전송합니다. `connectChat`은 개발 환경의 구독형 목 소켓에 연결하고, 900ms 뒤 상대 응답을 전달합니다. 실제 WebSocket/STOMP 연결이 아닙니다.
- 메시지·방 목록·읽음 상태는 사용자 ID별 sessionStorage에 보관합니다. 같은 탭에서 이동/새로고침해도 유지됩니다. 기기 간 동기화 및 서버 영속성은 Phase 3 대상입니다.
- 화면에 보이는 방은 수신 시 읽음 처리합니다. 다른 화면에서 도착한 메시지는 미읽음 수에 반영합니다. 알림 클릭은 해당 알림만, 전체 읽음은 모든 알림을 처리합니다.
- S10 및 S11은 같은 Room 객체와 RevealProgress를 사용합니다. 블러는 현재 목 단계에 따라 8/6/4/2/0px입니다. 실제 공개 단계별 마스킹 정책은 최종 사양 대조가 필요합니다.
- 신고 유형은 `backend/src/main/resources/db/migration/V2__seed_common_code.sql`의 REPORT_TYPE 5종입니다. 기타의 상세사유 필수, 상세사유 1000자 제한은 첨부 사양 미제공에 따른 임시 UX입니다.
- 신고는 `POST /api/mock/chat/:id/report`로 접수합니다. FRAUD/SEXUAL은 목 데이터에 `IMMEDIATE_REVIEW`, 나머지는 `STANDARD_REVIEW`로 기록합니다. 실제 S12 큐 연동은 포함하지 않습니다.
- 차단/나가기는 BMA-58 ConfirmModal을 재사용합니다. 차단 성공 토스트나 상대에게 보이는 차단 상태는 만들지 않습니다. 목 정책은 차단한 방의 송수신 전달을 억제하고, `excludedPartnerIds`에 매칭 영구 제외 대상을 기록합니다. 실제 매칭 엔진 적용은 서버 연동 시 수행해야 합니다.
- 차단당한 발신자도 동일한 성공 응답과 전송됨 표시를 받습니다. 전달은 생략합니다. 검증용 `bma-chat-safety-{userId}`의 `blockedBy`에 방 ID를 설정하여 재현할 수 있습니다. 이 데이터는 개발 목 내부에만 존재하며 실제 서비스에서는 차단 여부를 클라이언트에 내려주면 안 됩니다.
- 서버 오류 시 메시지 초안을 유지합니다. Enter 전송, Shift+Enter 줄바꿈, 한글 조합 중 Enter 전송 방지, 공백 전송 방지 및 4000자 제한을 적용했습니다.

## 미제공 사양 및 Phase 3

S11_스타일가이드_v1.3.pdf 및 S11_사양서_v1.3.xlsx는 저장소에 없습니다. 사용자 요청에 기재된 채팅/헤더/메뉴/신고 구성은 구현했지만, S11-01~12의 정확한 번호별 정의·치수·카피와 일치한다고 확정할 수 없습니다.

Phase 3에는 `src/api/chat.ts`의 전송/구독과 로컬 저장소를 실제 REST 및 인증된 WebSocket 이벤트로 교체해야 합니다. 재접속·히스토리 페이지네이션·서버 읽음 커서·매칭 제외 및 관리자 큐도 서버 계약에 맞춰 연동해야 합니다. 현재 백엔드 SafetyService는 차단 시 매칭 종료 동작이 있으므로, 상대에게 차단 사실이 드러나지 않도록 계약을 검토해야 합니다.

프로덕션 빌드에서는 목 소켓을 연결하지 않습니다. 채팅 전송은 비활성화되고 연결 준비 중 안내가 표시됩니다.
